# vcftools-ng v0.11.2

vcftools-ng v0.11.2 expands the output-compatible VCFtools 0.1.17 surface and
adds adaptive parallel input backends for Plain VCF, indexed BGZF VCF, and
indexed BCF.

## Highlights

- Individual statistics: `--depth`, `--missing-indv`, and `--het`.
- Site statistics: `--hardy`, `--site-quality`, π, Tajima's D, and FST.
- LD and PCA outputs, deterministic format conversion, and two-file
  comparison.
- Parallel aligned byte ranges for Plain VCF.
- Independent ordered TBI/CSI regions for BGZF VCF and BCF.
- Automatic CSI construction using the effective vcftools-ng thread budget.
- Protected CSI/TBI validation that never overwrites an existing sidecar.
- Bounded input → compute → ordered-commit pipeline with deterministic output.

The complete supported option matrix is organised by function in the
[README](https://github.com/VensinMa/vcftools-ng#supported-parameters).

## Exact compatibility

VCFtools 0.1.17 remains the compatibility oracle. The cumulative
2.3-million-record, 23-chromosome, 412-sample differential suite passes
byte-for-byte for the supported surface.

The final benchmark additionally used all 11,230,392 records:

- seven input/index scenarios;
- original VCFtools plus vcftools-ng at 1, 2, 4, 8, 16, and 32 threads;
- five strictly serial repeats for every combination;
- 245/245 successful runs;
- one identical output SHA-256 across all runs;
- source TBI/CSI hashes unchanged after validation.

## Full-dataset performance

Mean wall time on the 32-CPU benchmark host:

| Input path | Original | vcftools-ng 32 threads | Speedup |
|---|---:|---:|---:|
| BCF + CSI | 199.39 s | 10.74 s | 18.57x |
| BCF + automatic CSI | 198.45 s | 18.20 s | 10.91x |
| BGZF VCF + TBI | 296.69 s | 37.08 s | 8.00x |
| Plain VCF | 163.95 s | 28.65 s | 5.72x |
| BGZF VCF + automatic CSI | 297.06 s | 93.86 s | 3.17x |

Automatic-index timings include CSI construction. Complete 1/2/4/8/16/32
timings, CPU, RSS, and all five repeats are available in
[`benchmarks/results/final-full-v0112`](https://github.com/VensinMa/vcftools-ng/tree/master/benchmarks/results/final-full-v0112).

## Index policy

For a local BGZF VCF or BCF without a usable index, automatic mode invokes:

```text
bcftools index --csi --threads EFFECTIVE_THREADS
```

Use `--no-auto-index` to retain streaming behavior. Existing CSI and TBI
sidecars are validated independently and are never overwritten. Plain VCF is
not indexable by CSI/TBI and remains on its parallel byte-range backend.

## Build

Required development libraries are HTSlib, LAPACK, zlib, and POSIX threads.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DHTSLIB_ROOT=/path/to/htslib
cmake --build build -j
ctest --test-dir build --output-on-failure
```

## Known scaling limits

- Unindexed BGZF remains limited by the ordered decompression/framing path.
- The two-thread resource split is slower than the one-thread path in several
  input scenarios and remains an optimisation target.
- BCF without an index reaches its useful ceiling at approximately 16 threads
  on the benchmark host.
