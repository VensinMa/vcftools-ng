# vcftools-ng v0.11.3 — Adaptive Direct Text-to-Count Fusion

v0.11.3 fixes the one- and two-core regressions in the unfiltered `--counts`
workload and extends the new fused path through all 32 CPUs available on the
benchmark host.

## Highlights

- Direct VCF text-to-count fusion avoids intermediate `bcf1_t` construction
  and repeated FORMAT/GT decoding.
- Plain VCF uses aligned byte ranges with persistent file descriptors and a
  concurrency-scaled 256 MiB active input-buffer target.
- BGZF VCF with TBI/CSI uses ordered tabix regions from four threads upward.
- BGZF without an index uses the fused stream at low concurrency and can
  automatically build CSI for the higher-concurrency indexed path.
- Requested threads are capped by the process CPU allocation; workers are
  additionally constrained by the file-descriptor budget.
- Existing valid CSI/TBI sidecars remain protected and are never overwritten.

## Compatibility and performance

VCFtools 0.1.17 remains the oracle. The standard 2,300,000-record,
23-chromosome, 412-sample subset was tested in seven input/index scenarios
with vcftools-ng at 1, 2, 4, 8, 16, and 32 threads.

- 42/42 outputs were byte-identical.
- 42/42 runs were faster than original.
- Lowest observed speedup: 2.46×, Plain VCF at one thread.
- Highest observed speedup: 33.36×, BGZF VCF + TBI at 32 threads.
- BGZF + TBI improved from 18.59 seconds at one thread to 1.79 seconds at 32.
- Plain VCF improved from 12.69 seconds at one thread to 2.21 seconds at 32.

Automatic-CSI timings include first-run index construction. Full timings,
CPU, RSS, and exactness are in the
[v0.11.3 technical record](https://github.com/VensinMa/vcftools-ng/blob/master/docs/versions/v0.11.3.md).

The final 11,230,392-record matrix reused the five-run Original v0.11.2
baseline only after validating input paths, sizes, content hashes, and index
hashes. v0.11.3 then ran five times at each thread count. The first-run
byte-comparison gate passed for every configuration before repeats 2–5 began.
All 210 new outputs were byte-identical and faster than Original.

Five-run mean wall-clock seconds:

| Input path | Original | 1 thread | 2 threads | 4 threads | 8 threads | 16 threads | 32 threads |
|---|---:|---:|---:|---:|---:|---:|---:|
| BGZF VCF + TBI | 296.69 | 97.20 | 51.76 | 41.67 | 21.46 | 12.69 | 8.37 |
| BGZF VCF + automatic CSI | 297.06 | 96.92 | 51.44 | 49.10 | 77.88 | 69.39 | 64.92 |
| BGZF VCF, no automatic index | 293.28 | 96.34 | 51.09 | 49.03 | 48.99 | 48.96 | 49.03 |
| Plain VCF | 163.95 | 90.53 | 47.27 | 27.24 | 20.98 | 20.56 | 20.97 |
| BCF + CSI | 199.39 | 60.36 | 60.17 | 36.46 | 25.84 | 14.96 | 10.90 |
| BCF + automatic CSI | 198.45 | 60.54 | 60.05 | 71.56 | 43.76 | 25.07 | 18.66 |
| BCF, no automatic index | 198.44 | 61.32 | 62.20 | 55.47 | 28.14 | 16.50 | 16.02 |

The full-data speedup range was 1.81×–35.46×. Automatic-CSI timings include
building a fresh CSI in every measurement; indexed rows measure steady-state
parallel access.

## Install

```bash
curl -LO https://github.com/VensinMa/vcftools-ng/releases/download/v0.11.3/vcftools-ng-v0.11.3-linux-x86_64.tar.gz
curl -LO https://github.com/VensinMa/vcftools-ng/releases/download/v0.11.3/vcftools-ng-v0.11.3-linux-x86_64.tar.gz.sha256
sha256sum -c vcftools-ng-v0.11.3-linux-x86_64.tar.gz.sha256
tar -xzf vcftools-ng-v0.11.3-linux-x86_64.tar.gz
./vcftools-ng-v0.11.3-linux-x86_64/bin/vcftools-ng --version
```

The portable archive targets Linux x86_64 with glibc 2.17 or newer and
includes bcftools, HTSlib, and required non-glibc runtime libraries.
