# vcftools-ng v0.13.0 — Transactional BGZF Output and Hot-Path Acceleration

v0.13.0 makes compressed output the disk-safe default, hardens failure
handling, and accelerates the common seven-filter recode workload without
changing its VCFtools 0.1.17 scientific result.

## Highlights

- File-based `--recode` now writes deterministic BGZF VCF (`.vcf.gz`) by
  default; `--recode-vcf` explicitly selects uncompressed VCF and
  `--recode-vcf-gz` remains an accepted explicit compressed spelling.
- Scientific outputs use checked, same-directory staging and transactional
  publication. Failed writes preserve pre-existing destination files.
- Log-mirror failures no longer break stderr or scientific output.
- Floating-point parameters reject NaN and infinity.
- Automatic thread selection intersects affinity, cgroup, scheduler and
  hardware limits, with a 128-thread automatic ceiling.
- The common seven-filter direct kernel now covers Plain/BGZF VCF recode,
  shares DP/filter parsing, batches ordered text commits, reuses BGZF worker
  state, and keeps Plain VCF range descriptors open.
- Adaptive input/compute allocation was retuned across 4–32 local threads;
  unsupported workloads still fall back before publishing any output.
- The portable package exposes only `bin/vcftools-ng`; private bcftools 1.24
  and HTSlib 1.24 stay under `libexec`/`lib`.

## Full-data first-repeat release gate

The complete 11,230,392-record gate passed **108/108** configurations:

- inputs: BGZF+TBI, BGZF+automatic CSI, Plain VCF, adaptive BCF;
- outputs: SSD Plain VCF, SSD BGZF VCF, and same-HDD BGZF VCF;
- requested threads: 1/2/4/8/12/16/24/28/32.

All outputs matched the retained VCFtools 0.1.17 scientific goldens. Original
was not rerun because the version, inputs, filters, goldens, and hashes remain
locked. The published values use the validated first repeat only; incomplete
follow-up records were stopped and excluded from every reported timing.
For equivalent SSD uncompressed output, 32-thread speedups over Original were
79.57× (BGZF+TBI), 26.45× (BGZF+automatic CSI), 51.42× (Plain VCF), and
52.50× (adaptive BCF). The full report preserves the HDD Plain VCF I/O ceiling
rather than hiding the non-scaling rows.

### Storage-aware recommendation

- On high-performance SSD/NVMe storage with ample capacity, use
  `--recode-vcf` when minimum wall time matters most; it avoids compression
  but writes the larger uncompressed VCF.
- On conventional or slower HDD storage, keep the default `--recode` (or use
  `--recode-vcf-gz`) and prefer BGZF VCF input with a valid TBI/CSI index.
  Reducing both input and output traffic avoids the Plain VCF same-disk I/O
  ceiling measured by the release gate.

The measured result was 59.43 GB as Plain VCF and 10.20 GB as BGZF VCF. The
best choice can still vary with the filesystem, cache state, compression
ratio, shared-storage contention, and downstream workflow.

## Install

```bash
curl -LO https://github.com/VensinMa/vcftools-ng/releases/download/v0.13.0/vcftools-ng-v0.13.0-linux-x86_64.tar.gz
curl -LO https://github.com/VensinMa/vcftools-ng/releases/download/v0.13.0/vcftools-ng-v0.13.0-linux-x86_64.tar.gz.sha256
sha256sum -c vcftools-ng-v0.13.0-linux-x86_64.tar.gz.sha256
tar -xzf vcftools-ng-v0.13.0-linux-x86_64.tar.gz
./vcftools-ng-v0.13.0-linux-x86_64/bin/vcftools-ng --version
```

The archive targets Linux x86_64 with glibc 2.17 or newer and passed clean
CentOS 7 and Ubuntu 20.04 validation. Archive SHA-256:
