# vcftools-ng v0.13.1 — Adaptive Zero-Copy Population Analytics

v0.13.1 removes generic-pipeline overhead from common site-selection,
sample-projection, and population-statistics workloads while preserving exact
VCFtools 0.1.17 output.

## Highlights

- `--positions` and `--exclude-positions` use direct chromosome/POS lookup
  with Original-compatible duplicate, absent-position, and input-order rules.
- `--keep`, `--remove`, `--indv`, and `--remove-indv` project the selected
  samples before GT decoding. A 100% keep set becomes an identity projection.
- Sample selection, the seven production filters, statistics, and VCF recode
  can share the direct text scan when the combination is eligible.
- Window pi, Tajima's D, site FST, and window FST use compact per-site
  contributions followed by deterministic ordered reduction.
- Common diploid GT spellings and GT-first FORMAT fields use dedicated parsers.
- Two-population biallelic FST uses fixed stack accumulators.
- Multi-thread Plain VCF uses read-only mapped aligned ranges. One-thread
  mapping is limited to I/O-dominated position or sample-selection workloads;
  `mmap` failure safely falls back to the checked `pread` path.
- Logs expose `zero-copy mapped aligned ranges` when the mapped backend is
  selected.

## Locked exactness and performance matrix

The 23,000-record development gate passed **285/285** configurations across
1/4/8/16/32 threads, including an independent 205-sample GATK multiallelic
FST case. The 230,000-record, 412-sample performance gate passed **225/225**
complete byte comparisons against permanent VCFtools 0.1.17 oracles.

At 32 threads, the 15 W03-W10 workloads were **8.17x-29.21x** faster than
Original. Relative to the frozen pre-optimization vcftools-ng candidate, the
same 32-thread workloads improved by **31.2%-60.0%**. Representative median
wall times:

| W05 keep 50% + counts | 3.94 | 1.61 | 0.45 | 0.27 | 0.22 | 0.15 | 26.27x |
| W07 overlapping window pi | 4.16 | 2.68 | 0.66 | 0.38 | 0.32 | 0.20 | 20.80x |
| W09 large-pair site FST | 4.55 | 2.58 | 0.70 | 0.39 | 0.33 | 0.22 | 20.68x |
| W10 biallelic window FST | 4.55 | 2.60 | 0.71 | 0.41 | 0.33 | 0.21 | 21.67x |

## Memory interpretation

Mapped Plain VCF pages are reclaimable file-backed pages rather than
equivalent anonymous heap. Linux peak RSS can nevertheless approach the
accessed input size. The 3.20 GB 230k input reported approximately 3.06 GB RSS
for mapped workloads and approximately 133 MiB for one-thread pi/Tajima
`pread` paths. Results must therefore be interpreted together with storage,
major page faults, and host memory pressure.
