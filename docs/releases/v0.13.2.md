# vcftools-ng v0.13.2 — Exact Fused Kernels and Parallel Analytics

v0.13.2 expands exact fast-path coverage to production genotype/depth/frequency
filters, FILTER/INFO/FT, no-index BGZF input, LD, PCA, and indexed BCF diff.

## Highlights

- The real ten-filter workload now shares one direct GT/GQ/DP pass.
- DeepVariant/GATK FORMAT layouts use cached dedicated parsers.
- Real-data GT coverage includes phased, partially missing, haploid-missing,
  and multiallelic calls; reverse, called-haploid, and multi-digit forms have
  an Original-locked generic-fallback gate.
- GT grammar is separated from analysis semantics: site-only VCF recode can
  preserve polyploid sample text, while genotype statistics and masking reject
  unsupported ploidy transactionally.
- Site FILTER, INFO Flag, genotype FT, SNP/indel, and shared `--site-pi`
  workloads can use the direct text kernel.
- Window pi uses an exact integer range accumulator; Tajima/FST preserve
  Original floating accumulation order.
- BGZF without TBI/CSI overlaps inflate, record batching, compute, and ordered
  commit without exceeding the requested thread budget.
- Biallelic diploid LD uses bit planes and popcount.
- Exact PCA uses a contiguous dosage matrix without changing cell summation
  order.
- Indexed BCF discordance diff parallelizes by contig.
- Release IPO/LTO is automatic when supported; reproducible PGO is opt-in.

## Validation

- v0.13.2 fixed 23k gate: **45/45 PASS** at 1/4/8/16/32 threads.
- Final broad W01-W10 23k gate: **95/95 PASS**.
- Eleven scientific oracle artifacts are hash-locked and byte-compared.
- Generic/specialized scalar parsers match on synthetic, DeepVariant, and GATK
  gates; five triploid forms have rejection and opaque-passthrough coverage.
- Release tests without the deferred 2.3m differential: **7/7 PASS**.
- ASan+UBSan base and directed new-kernel gates: **PASS**.
- No 2.3m or 11.23m benchmark was run or inferred for this candidate.

On the locked 230k fixture, the real ten-filter count path is approximately
2.10x faster than v0.13.1 at one thread and 2.79x-2.85x faster at 8-32
threads. No-index BGZF ten-filter processing improves approximately 8.43x at
32 threads relative to the v0.13.1 path. Full details are in the
[technical record](../versions/v0.13.2.md) and
[development evidence](../../benchmarks/results/v0132-development-gate/README.md).
