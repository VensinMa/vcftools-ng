# vcftools-ng v0.14.3 — Strict CPU Budget Recovery

v0.14.3 fixes `--threads N` so it is a real whole-workflow CPU budget while
preserving exact VCFtools-compatible scientific output and v0.14.2-class
performance.

## Highlights

- Linux restricts vcftools-ng and automatic bcftools children to at most N
  runnable CPUs using a dynamic affinity set.
- Waiting input, decompression, compute, and BGZF output workers can overlap,
  avoiding idle CPUs without increasing the process CPU capacity.
- Hidden HTSlib/bcftools coordinators, BCF serialization, diff, LD, PCA, and
  vendor BLAS runtimes are covered by the budget audit.
- Automatic selection still intersects scheduler, affinity, cgroup, and
  hardware limits and caps only the omitted-`--threads` case at 128. Explicit
  values can scale to larger server allocations.
- Output bytes are unchanged. The 2.3-million-record differential and the
  230k production-filter SHA gates passed.

## Validation

- Release CTest: 10/10 PASS.
- ASan+UBSan: no findings in applicable tests.
- Fair 4/8/16/24/32-thread v0.14.2 comparison: every delta within ±5%.
- Linux x86_64 archive: glibc 2.17+; public `bin` contains only
