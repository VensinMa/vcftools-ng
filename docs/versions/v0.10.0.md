# vcftools-ng v0.10.0

Status: **complete for the compatibility surface documented below**.

v0.10.0 expands the shared decode engine from site summaries and filtering
to individual statistics, ordered population/window statistics, LD, PCA,
deterministic format conversion, and the four most frequently used two-file
comparison outputs.

## Parameters added

### Individual and site statistics

- `--depth` → `.idepth`
- `--missing-indv` → `.imiss`
- `--het` → `.het`
- `--hardy` → `.hwe`
- `--site-quality` → `.lqual`

### Population and window statistics

- `--site-pi` → `.sites.pi`
- `--window-pi N`, `--window-pi-step N` → `.windowed.pi`
- `--TajimaD N` → `.Tajima.D`
- repeated `--weir-fst-pop FILE`
- `--fst-window-size N`, `--fst-window-step N`
- site FST → `.weir.fst`; windowed FST → `.windowed.weir.fst`

### LD and PCA

- `--geno-r2`
- `--ld-window`, `--ld-window-min`
- `--ld-window-bp`, `--ld-window-bp-min`
- `--min-r2`

- `--diff-site-discordance` → `.diff.sites`

## Architecture

Each in-flight batch owns compact structure-of-arrays rows for per-sample
state, depth, and genotype dosage. Workers write disjoint rows after a single
GT/DP/GQ/FT decode. Ordered commit applies `--thin` and then performs every
floating-point accumulation in original site order.

The same accepted genotype store feeds LD and PCA. LD pair calculations are
partitioned by left site and committed in left-site/right-site order. PCA
matrix cells are parallel, while each cell consumes variants in original
order before the original LAPACK `dgeev` ordering is reproduced.

BCF conversion preserves the input BCF header bytes and serializes record
payloads through HTSlib. A deterministic BGZF writer splits the raw stream
into the original 65,280-byte blocks, compresses blocks in parallel, and
writes them by block number. Therefore 8 and 16 threads produce the same
container bytes. The same writer compresses the already-compatible textual
VCF stream for `--recode-vcf-gz`.

The diff engine performs a sorted two-stream merge. Site and individual
discordance share genotype decoding and intentionally retain original
VCFtools behavior for partially missing diploid genotypes.

## Compatibility validation

- Main fixture: 2,300,000 real records, 23 chromosomes, 412 samples.
- Semantic fixture: 23,000 real records with FILTER, INFO Flag, and FT
  annotations.
- Original oracle: VCFtools 0.1.17.
- Main original input: equivalent BGZF VCF; vcftools-ng input: BCF.
- All text comparisons use `cmp` over complete files.
- Exact BCF validation compares the complete compressed BCF byte stream.
- `--recode-vcf-gz` has no original compressed-output counterpart; its
  decompressed VCF is compared byte-for-byte with original `--recode`, and
  its compressed bytes are deterministic across 8 and 16 threads.
- Full regression: `ctest`, 91.15 seconds, 1/1 passed.

The formal goldens include 2.3-million-record individual/HWE/quality, π,
FST, LD, PCA, and diff results. The semantic gate additionally exercises
sample selection, GQ/DP/FT masking, thinning, window boundaries, all four
diff modes, BCF conversion, and compressed VCF conversion.

## Deliberate compatibility boundaries

- Exact raw BCF output currently requires BCF input, no sample subsetting,
  and no genotype masking. The raw header is preserved. VCFtools 0.1.17
  corrupts genotypes on its BCF-input plus genotype-filtering output path,
  while its VCF-input BCF writer cannot represent this fixture's header;
  therefore no trustworthy original binary golden exists for that
  combination. Unsupported cases fail explicitly.
- Exact PCA currently requires complete genotypes (`--max-missing 1`).
  VCFtools 0.1.17's PCA path has undefined/misaligned behavior with missing
  genotypes, so no stable golden exists for that case.
- The v0.10 diff engine accepts chromosome, position, BED, and sample
  selection filters. Other filters must be applied before comparison.
- `--diff-site` is not combined in one scan with discordance outputs when
  overlapping indels may require different merge consumption.
- Haplotypic LD, interchromosomal LD, discordance matrix, switch error, and
  every remaining legacy format are future compatibility slices.
