# vcftools-ng v0.11.2

Status: **complete for protected, explicit CSI/TBI validation and Plain VCF
index policy**.

## Plain VCF decision

CSI and TBI store BGZF virtual offsets. They cannot directly index an
uncompressed VCF. `bcftools index` accepts BGZF VCF and BCF, not Plain VCF.
Converting Plain VCF to BGZF would create a different data file and is not an
implicit indexing operation.

vcftools-ng therefore keeps Plain VCF on its aligned-byte-range backend. It
does not invoke bcftools and does not create `.csi` or `.tbi` for Plain VCF.

## Valid sidecar selection

For local BGZF VCF/BCF, `.csi` and `.tbi` are inspected independently, with
CSI preferred when both are valid. Validation checks:

1. the sidecar is a readable regular file;
2. the sidecar is not older than the data file;
3. HTSlib can explicitly load that exact sidecar;
4. VCF tabix metadata uses the VCF preset;
5. indexed sequence names/counts are compatible with the VCF/BCF header;
6. per-sequence index statistics are readable;
7. the first indexed record of every non-empty sequence can be retrieved and
   belongs to the expected contig.

The selected path is passed explicitly to every worker. This means a damaged
`.csi` cannot mask an otherwise valid `.tbi`. The selected path is also
reported in the input-backend description.

TBI/CSI do not contain a cryptographic checksum of the complete data file, so
no implementation can prove byte-for-byte association from the sidecar
alone. The mtime, metadata, statistics, and per-contig random-access probes
are the strongest bounded preflight available without scanning the entire
VCF/BCF.

## No-overwrite policy

- Any valid sidecar is reused and never rebuilt.
- If one sidecar is invalid but the other is valid, the valid sidecar is
  selected and the invalid file is left untouched.
- If sidecar paths exist but none is valid, automatic mode warns and falls
  back to the stream. It does not overwrite, rename, or delete user files.
- Forced `--input-backend indexed` fails with the validation reason.
- A newly built CSI is validated before atomic no-replace publication.
- Concurrent builders revalidate sidecars while holding the input lock.

Automatic indexing remains enabled by default. `--no-auto-index` has no
effect unless the user explicitly supplies it; when supplied, absence of an
index does not invoke bcftools.

## Validation

The backend regression covers Plain VCF, valid TBI/CSI, corrupt CSI, stale
TBI, corrupt CSI plus valid TBI, no-index auto construction, explicit
`--no-auto-index`, scheduler-derived threads, missing bcftools, and concurrent
builders. Original index hashes are checked before and after the test.

Full cumulative `ctest`: 2/2 passed. The backend regression took 7.77 seconds
and the cumulative differential compatibility test took 108.11 seconds.
After adding the selected-path log assertion, the backend regression was
rerun and passed in 7.70 seconds.

## Final full-dataset benchmark

The final `--counts` matrix used all 11,230,392 records and 412 samples. Seven
input/index scenarios were run strictly serially with original VCFtools
0.1.17 and vcftools-ng at 1, 2, 4, 8, 16, and 32 threads. Every combination
was repeated five times, for 245 runs in total. The operating-system cache was
not flushed between runs.

All 245 commands exited successfully. The seven first original runs were the
scenario oracles and the remaining 238 comparisons passed `cmp`. Every output
had SHA256
`363718e253bbb41db8d9ba255b858d5d70577388a515ace7678f30ab60e1f9ce`.
Existing TBI and CSI hashes were unchanged after the benchmark.

Mean wall-clock seconds are shown below; parenthesised values are speedups
against the original mean for the same scenario.

and framing limited, while the two-thread resource allocation path remains a
separate optimisation target.
