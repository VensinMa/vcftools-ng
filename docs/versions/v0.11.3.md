# vcftools-ng v0.11.3

Status: **complete for adaptive unfiltered `--counts` fusion, the
1/2/4/8/16/32-thread real-subset gate, and the five-repeat full-data gate**.

## Scope

v0.11.3 removes the generic record-object pipeline from the most common
unfiltered `--counts` workload:

- Plain VCF is split at complete-line byte boundaries. Persistent workers use
  independent file descriptors, parse FORMAT/GT directly, and emit final
  VCFtools-compatible count lines.
- BGZF VCF uses direct streaming GT counting at one and two threads. At four
  or more threads, a valid TBI/CSI selects ordered tabix coordinate windows;
  every worker overlaps region decompression, line parsing, GT counting, and
  final formatting.
- A missing BGZF index stays on the fused stream at low thread counts. Above
  four threads, normal automatic-index policy may build CSI and enter the
  indexed fused path. `--no-auto-index` always preserves streaming.
- Ordinary gzip VCF uses the direct streaming parser.
- BCF retains the v0.11.2 adaptive backend because direct VCF text parsing
  does not apply.

The effective worker count is capped by process CPU availability and the
file-descriptor budget. Plain-VCF shard bytes shrink with concurrency so the
active input-buffer target stays near 256 MiB instead of growing as
64 MiB × requested threads.

No new VCFtools parameter was added. The cumulative supported surface remains
the v0.11.2 surface; this release changes execution of eligible `--counts`
commands only.

## Exact compatibility

Oracle: VCFtools 0.1.17.

Development fixture: 2,300,000 real records, 100,000 from each of 23
chromosomes, 412 samples. Seven input/index scenarios were run strictly
serially. For every scenario, original ran once and vcftools-ng ran at 1, 2,
4, 8, 16, and 32 threads.

All 42 vcftools-ng outputs passed byte comparison. Every output SHA-256 was:

```text
c2d9a316a7630f092eeec8ab89043f0a5dcc2b0bd579da95b2776bae566731cd
```

The cumulative CTest suite also passed:

- input backend differential: PASS;
- complete supported-surface differential compatibility: PASS;
- adaptive counts at 1/2/4/8/16/32, automatic CSI, no-index policy, unusual
  GT layouts, and polyploid rejection: PASS.

The final fixture contained all 11,230,392 records. The five previously
measured Original runs per scenario were reused only after validating the
input paths, sizes, BGZF and BCF SHA-256 hashes, and CSI/TBI SHA-256 hashes.
vcftools-ng was then run five times at each of 1, 2, 4, 8, 16, and 32
threads. The first run at every thread count passed `cmp` before repeats 2–5
were permitted to start.

All 210 new full-data candidate outputs were byte-identical to their Original
oracle. Together with the 35 validated Original records, the final matrix
contains 245 measurements.

## Final full-data performance

Five-run mean wall-clock seconds on the same 32-CPU host:

| Scenario | Original | ng1 | ng2 | ng4 | ng8 | ng16 | ng32 | ng32 speedup |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| BGZF + TBI | 296.69 | 97.20 | 51.76 | 41.67 | 21.46 | 12.69 | 8.37 | 35.46× |
| BGZF + automatic CSI | 297.06 | 96.92 | 51.44 | 49.10 | 77.88 | 69.39 | 64.92 | 4.58× |
| BGZF, no automatic index | 293.28 | 96.34 | 51.09 | 49.03 | 48.99 | 48.96 | 49.03 | 5.98× |
| Plain VCF | 163.95 | 90.53 | 47.27 | 27.24 | 20.98 | 20.56 | 20.97 | 7.82× |
| BCF + CSI | 199.39 | 60.36 | 60.17 | 36.46 | 25.84 | 14.96 | 10.90 | 18.29× |
| BCF + automatic CSI | 198.45 | 60.54 | 60.05 | 71.56 | 43.76 | 25.07 | 18.66 | 10.63× |
| BCF, no automatic index | 198.44 | 61.32 | 62.20 | 55.47 | 28.14 | 16.50 | 16.02 | 12.39× |

All 42 candidate configurations were faster than Original. The lowest
full-data speedup was 1.81× for Plain VCF at one thread; the highest was
35.46× for BGZF + TBI at 32 threads. At 32 threads, mean CPU utilisation
ranged from 226% for the deliberately streaming no-index BGZF path to 2,972%
for indexed BGZF. Maximum RSS ranged from 14,948 KiB to 346,372 KiB.

Automatic-CSI rows include removing any generated CSI before each run and
building it again. Their means therefore represent first-run latency rather
than steady-state indexed access.
