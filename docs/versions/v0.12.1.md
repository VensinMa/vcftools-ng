# vcftools-ng v0.12.1

Subtitle: **Fused Site Statistics and Scalable Exact Recode**.

Status: **released after the complete first-repeat seven-scenario gate;
repeats 2–5 are pending**.

## Scope

v0.12.1 broadens the direct VCF-text statistics path and hardens the exact
recode pipeline:

- `--freq`, `--freq2`, `--counts`, `--missing-site`, `--site-depth`,
  `--site-mean-depth`, and `--site-quality` can share one direct parse and
  one ordered scan for eligible Plain/BGZF VCF workloads.
- Plain VCF uses aligned byte ranges; indexed BGZF uses ordered tabix regions.
- Fused worker output is bounded by backpressure while the fixed-order
  committer preserves byte order.
- Exact recode workers use independent duplicated HTSlib output headers,
  removing shared lazy header mutation while retaining parallel formatting.
- The generic bounded input → compute → ordered-output pipeline remains the
  compatibility fallback for filters, BCF, and unsupported fast-path
  combinations.

No Original parameter name was invented for compressed VCF output:
`--recode-vcf-gz` is explicitly documented as a vcftools-ng-only extension.
The complete classification is in
[parameter-compatibility.md](../parameter-compatibility.md).

## Safety and compatibility

Before the release gate:

- the final normal CTest suite passed 3/3 in 125.26 seconds;
- the final ASan/UBSan CTest suite passed 3/3 in 303.04 seconds;
- the new 2.3-million-record fused statistics gate passed 8/8;
- the reviewed three-scenario seven-filter recode gate passed 18/18 at
  1/2/4/8/16/32 threads.

The sanitizer review found and fixed a real shared-header issue in
multithreaded VCF recode. A per-worker `bcf_hdr_dup` regression run then
passed the full sanitizer suite.

Exact mode intentionally reproduces documented VCFtools 0.1.17 bytes when
the oracle has observable quirks. Unsafe combinations for which Original
produces corrupt or undefined output are rejected. See the parameter matrix
for the BCF structured-header, BCF masking/recode, missing-PCA, partial-missing
diff, non-reference, and polyploid boundaries.

## Full-data first-repeat release gate

The release candidate commit
`f33751479f875a962039d92bd4ba17753d5bef15` was tested on 11,230,392 real
records, 23 chromosomes, and 412 samples. Seven real-project filters retained
5,425,725 records:

```text
--min-alleles 2 --max-alleles 2 --minGQ 10 --minQ 30
--min-meanDP 7 --max-missing 0.9 --maf 0.1
--recode --recode-INFO-all --stdout
```

VCFtools 0.1.17 generated a new oracle for each actual input format. Seven
vcftools-ng input/index scenarios then ran strictly serially at
1/2/4/8/16/32 threads. All 42 outputs passed complete-file `cmp`; all 42 were
faster than Original in the first repeat.

speedup range was 4.11×–48.24×. Automatic-CSI timings include fresh index

threads upward, while no-index BCF was faster than automatic CSI at every
tested thread count. This is measurement context only; the automatic-index
policy is unchanged and users can select `--no-auto-index`.
