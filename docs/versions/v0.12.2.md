# vcftools-ng v0.12.2

Subtitle: **Workload-Adaptive Indexing and Exact Recode Scaling**.

Status: **released after the full four-scenario, five-repeat gate passed**.

## Scope

v0.12.2 makes indexing a workload-dependent acceleration technique instead
of a format-wide default:

- Plain VCF streams at 1–2 threads and uses aligned byte ranges at 3+ threads.
- Full-file BGZF VCF recode streams at one thread, then reuses or builds an
  index at 2+ threads.
- Full-file BCF recode streams at every tested thread count, even when a CSI
  exists.
- Selective chromosome/coordinate BGZF and BCF queries still reuse or build a
  valid index.
- Compact full-scan statistics reuse an existing index from four threads but
  do not build a one-use index.
- Existing `.tbi` and `.csi` sidecars are validated independently and never
  overwritten.
- `--no-auto-index` is removed. `--input-backend stream|indexed` remains an
  advanced explicit override.

The compatible Original parameter surface is unchanged. These changes select
faster execution paths without changing exact-mode output bytes.

## Validation before the full gate

- Release CTest: 4/4 passed, including the 2.3-million-record differential
  suite.
- ASan/UBSan CTest: 4/4 passed with no sanitizer finding.
- Real 23,000-record release-driver smoke: 24/24 first-repeat configurations

- Real 2.3-million-record daily gate: 18/18 BGZF+TBI, Plain VCF, and adaptive
  BCF configurations passed at 1/2/4/8/16/32 threads.

## Full-data release matrix

Candidate commit `8980655d83b9b161fe558ce7d2d2a784289acc2a` was frozen before
the full run. The input contained 11,230,392 records across 23 chromosomes and
412 samples. Seven real-project filters retained 5,425,725 records:

```text
--min-alleles 2 --max-alleles 2 --minGQ 10 --minQ 30
--min-meanDP 7 --max-missing 0.9 --maf 0.1
--recode --recode-INFO-all --stdout
```

The v0.12.1 Original outputs and timings were reused after validating the
input, index, and oracle SHA-256 values. Original runs performed for v0.12.2:
**zero**. Each vcftools-ng configuration ran five times in strict serial
order. Every repeat performed a complete-file `cmp`, SHA validation, and
backend assertion.

- 4 input scenarios;
- 6 thread counts: 1/2/4/8/16/32;
- 5 repeats per configuration;
- 120/120 vcftools-ng outputs byte-identical;
- mean speedup range: 5.97×–53.59×.

Mean wall-clock seconds:

| Scenario | ng1 | ng2 | ng4 | ng8 | ng16 | ng32 |

| BGZF + TBI | 7.33× | 11.07× | 20.19× | 30.68× | 43.57× | 53.59× |

At 32 threads:

| Scenario | Mean CPU | Maximum RSS |
|---|---:|---:|
| BGZF + TBI | 2146.2% | 507,764 KiB |
| BGZF + automatic CSI | 1144.2% | 514,280 KiB |
| Plain VCF | 1545.0% | 1,189,116 KiB |

Plain VCF peaked at 16 threads in this workload; 32 threads was slightly
slower, so no monotonic-scaling claim is made. BCF streaming removes the
large indexed full-scan RSS cost and nearly halves v0.12.1 two-thread BCF
time while preserving exact bytes.
