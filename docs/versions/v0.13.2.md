# vcftools-ng v0.13.2 — Exact Fused Kernels and Parallel Analytics

## Scope

Status: **release candidate validated on locked 23k correctness and 230k A/B
fixtures; no 2.3m or 11.23m result is inferred**.

v0.13.2 broadens the exact fast-path family beyond v0.13.1 selection and
population reduction. It targets the production ten-filter combination,
FILTER/INFO/FT, no-index BGZF, LD, PCA, and indexed BCF diff while preserving
VCFtools 0.1.17 scientific bytes. There is no fast-math or tolerance gate.

## Runtime implementation

1. The direct text plan now fuses genotype `minDP/maxDP`, `max-meanDP`,
   missing-count, `max-maf`, MAC, exact HWE, and non-reference AF/AC filters.
   The real ten-filter combination performs one GT/GQ/DP sample pass.
2. Worker-local FORMAT caches avoid reparsing unchanged layouts. Dedicated
   parsers cover the observed DeepVariant
   `GT:DP:AD:GQ:PL:RNC:FT` and GATK `GT:AD:DP:GQ:*` layouts; the generic parser
   remains the exact fallback. GT decoding covers the real phased,
   partially-missing, haploid-missing, and allele-2-to-4 forms; a dedicated
   Original gate additionally covers reverse/order variants, called haploids,
   and multi-digit allele indices. Common one-byte haploid and three-byte
   diploid tokens use allocation-free scalar fast paths. A test-only parser
   override forces generic or specialized scalar decoding over identical
   inputs, establishing the differential framework required by future SIMD.
3. Site FILTER, INFO Flag, genotype FT, and SNP/indel filtering can enter the
   direct kernel. Transparent set lookup removes per-token string allocation.
   `.lmiss` reports Original-compatible filtered-genotype counts.
4. Advanced site contributions use shard-local numeric chromosome IDs and
   vector-indexed reducers. Window indexing is integer-only. Overlapping pi
   uses an integer difference array, changing the reducer from per-overlap
   updates to range endpoints plus one prefix scan.
5. `--site-pi` can share the fused scan with compatible site outputs.
6. No-index BGZF VCF uses HTSlib parallel inflate, bounded 8 MiB record
   batches, parallel compute, and ordered commit. At most eight batches are in
   flight. Reader, I/O, and compute share the strict total thread budget.
7. Biallelic diploid `--geno-r2` uses valid/dosage bit planes and 64-bit
   popcount. Integer sufficient statistics feed the unchanged Original
   floating formula.
8. Exact PCA stores eligible dosages contiguously, precomputes per-site mean
   and divisor, and schedules upper-triangle rows. Every covariance cell still
   accumulates sites in input order.
9. Indexed BCF site/individual discordance diff runs independent contigs in
   parallel and publishes by the first input header. Unsupported diff shapes
   retain the serial compatibility path.
10. Release builds enable supported IPO/LTO. An explicit two-stage PGO flow is
    available through `benchmarks/build-pgo.sh`; PGO is opt-in and does not
    change scientific bytes.
11. GT grammar and analysis semantics are separate. Site-only filtering and
    raw VCF recode keep polyploid sample fields opaque; any path that requests
    genotype statistics or genotype masking rejects ploidy above two before
    scientific outputs are committed.

## Exactness and safety evidence

- Fixed v0.13.2 development gate: 9 workload families x 5 thread counts =
  **45/45 PASS** at 1/4/8/16/32 threads.
- Final broad W01-W10 candidate gate: 19 workloads x 5 thread counts =
  **95/95 PASS** against locked 23k oracles.
- Eleven locked oracle artifacts pass SHA-256 verification before every gate.
- INFO keep/remove: **10/10 byte PASS** plus rejection of non-Flag INFO fields.
- GT syntax: Original byte comparison covers phased/unphased, leading and
  trailing partial missingness, called/missing haploids, multiallelic
  diploids, reverse heterozygotes, and multi-digit allele indices. The real
  DeepVariant/GATK token census is retained with the development evidence.
- Generic versus specialized scalar parser differential: synthetic GT grammar,
  DeepVariant, and GATK outputs all match their locked references. Invalid
  override values fail transactionally.
- Five triploid forms reject on semantic commands without crashes or partial
  scientific artifacts. Site-only `--minQ` and `--positions` recode preserve
  the same opaque GT text at 1 and 32 threads.
- Existing W01-W10 PGO candidate matrix: all 23k cases byte-identical.
- Release tests excluding the intentionally deferred 2.3m differential test:
  **7/7 PASS**.
- ASan+UBSan for the same suite: **7/7 PASS**.
- Directed ASan+UBSan gate covering filters, INFO/FT, no-index BGZF, LD, PCA,
  indexed diff, and shared site pi/counts: **PASS**.
- 3-thread compressed budget: reader 1 + HTSlib I/O 1 + compute 1.
- 4-thread compressed budget: reader 1 + HTSlib I/O 2 + compute 1.

The fixed runner, environment, oracle hashes, and compact results are in the
[v0.13.2 development record](../../benchmarks/results/v0132-development-gate/README.md).

## Measured 230k changes versus v0.13.1

Representative three-run means on the same 32-logical-CPU SSD host:

| Workload | Threads | v0.13.1 | v0.13.2 | Gain |
|---|---:|---:|---:|---:|
| Ten-filter counts | 1 | 6.73 s | 3.21 s | 2.10x |
| Ten-filter counts | 8 | 1.22 s | 0.43 s | 2.84x |
| Ten-filter counts | 16 | 0.92 s | 0.33 s | 2.79x |
| Ten-filter counts | 32 | 0.57 s | 0.20 s | 2.85x |
| Site FILTER counts | 1 | 6.70 s | 1.13 s | 5.93x |
| Site FILTER counts | 32 | 0.54 s | 0.11 s | 4.91x |
| No-index BGZF ten-filter | 8 | 6.63 s | 0.72 s | 9.21x |
| No-index BGZF ten-filter | 32 | 6.66 s | 0.79 s | 8.43x |

Pair-dense 23k LD improves from 2.52 to 1.13 seconds at one thread and from
0.18 to 0.11 seconds at 32 threads. A 100k indexed BCF discordance workload
improves from 30.12 to 15.83 seconds at two threads and from 8.94 to 2.00
seconds at 32 threads. Exact PCA gains are modest: approximately 2%-4% on the
measured low-missing 64-sample fixture and effectively neutral at the highest
thread counts.

LTO contributes approximately 4%-7% in the measured 16/32-thread site-local
cases. Optional PGO improves the LTO build by 16%-34% in the recorded 230k
counts/ten-filter matrix. These are build-specific measurements, not universal
speedup promises.

## Boundaries

The following proposals were audited but are not claimed as completed:

- a direct raw-BCF filter/statistics decoder;
- moving BCF record serialization out of the ordered lane;
- runtime AVX2/AVX-512 parser dispatch; and
- NUMA placement for multi-socket 64-128+ core hosts.

They require new independent exactness and scaling gates. Existing v0.13.1
position/sample-selection performance and v0.13.0 full-data recode/storage
evidence remain inherited historical results rather than relabeled v0.13.2
benchmarks.
