### QueryPlan and PGO update

The immutable `QueryPlan` is now implemented. It replaces the former separate
fused-eligibility and generic-field plans, supplies a precise logged fallback
reason, and passes a compact capability mask to fused workers without changing
the hot `FastSiteStatPlan` layout. `run_logging`, reliability, GATK, adaptive
counts, and adaptive index gates pass. The latest ASan/UBSan directed gate is
4/4 PASS (`run_logging`, reliability, GATK, adaptive counts; 46.07 seconds).

The existing generic and fused engines were audited for multi-analysis
execution. Both already perform one input/record/sample scan and feed all
compatible outputs from a shared decode; LD and PCA reuse the dosage payload
for their unavoidable post-scan calculations. A second analysis-lane queue
was therefore rejected because it would add payload copies and synchronization
without eliminating a scan. The decision is recorded in
`docs/architecture/query-plan.md`.

Current-source PGO was retrained on the locked 23k workload mix and compared
against the same-source Release+LTO binary on the 230k Plain VCF. All 120 runs
passed their locked output gates. Three-repeat mean wall-time changes were:

|---|---:|---:|---:|---:|
| W01 counts | -15.11% | -13.51% | -12.90% | -7.14% |
| W02 ten filters | -13.97% | -10.00% | -10.10% | -7.69% |
| W06 sample recode | -9.25% | -7.55% | -2.22% | -6.32% |

v0141-pgo-interleaved-ab/`. PGO remains opt-in for source builds; use it for a

PGO was subsequently checked on 230k BGZF+TBI and no-index BGZF W01/W02 at
1/8/16/32 threads. Indexed gains were 6.43-12.67% for W01 and 7.26-11.17%

## Completed Phase A work before the pause

1. HTSlib stream/iterator return codes now distinguish normal EOF (`-1`) from
   truncated, malformed, CRC, or I/O failures (`< -1`) in the generic and
   fused input implementations.
2. A truncated BGZF regression verifies nonzero exit, no published scientific
   artifact, and no staged-file leak.
3. A previously unknown crash was found and fixed:
   - a legal VCF without `##contig` declarations produced `RID=-1` in the
     parallel Plain VCF implementation;
   - combining individual and site-depth outputs then dereferenced a null
     chromosome name at three or more threads;
   - automatic mode now selects the ordered stream for such headers;
   - explicitly forcing `--input-backend plain` fails clearly;
   - a final defensive chromosome validation prevents null dereference.
4. Output rollback failures are no longer silent. A preserved private backup
   and the intended restore destination are printed for manual recovery.
5. Reader and worker fail-after-N hooks verify cancellation, thread joining,
   timeout-bounded exit, transaction abandonment, and no partial artifacts.
6. Runtime-generated reliability cases cover:
   - a VCF record larger than 8 MiB;
   - a final record without a newline;
   - CRLF input;
   - serial versus parallel text-output equality.
7. Original VCFtools 0.1.17 depth arithmetic was reproduced and documented as
   `OVI-013`:
   - `SUM_DEPTH` and `SUMSQ_DEPTH` wrap as unsigned 32-bit values;
   - zero/one DP observations expose Original `-nan` formatting;
   - `numeric-edge.vcf` and Original-generated goldens lock these bytes.
8. The reliability test passed after the crash, transaction, fault-injection,
   truncated-BGZF, long-record, and CRLF changes.

## Complete remaining plan

### 1. Finish Phase A correctness and reliability

- Complete checked depth arithmetic without changing exact defaults.
- Add degenerate called/missing/window/FST fixtures.
- Add mixed-ploidy-in-the-middle, multiallelic 15/16/17, population-file, and
  unsorted-input oracle gates.
- Extend reader/worker/compressor/writer failure injection where evidence
  reveals an uncovered wait or publication path.
- Re-run Release and ASan/UBSan gates.

### 2. Unify the text ordered-shard seam

- Create one deep ordered text-shard interface for Plain VCF, indexed BGZF,
  and no-index BGZF.
- Share resource planning, cancellation, backpressure, error propagation,
  record ordinal, and stage metrics.
- Preserve the current scheduling constants until byte equality passes.

### 3. Reduce per-record CPU and memory traffic

- Implement `ParsedRecordLayout` so fixed columns, sample spans, FORMAT
  offsets, genotype masking, statistics, and recode reuse one layout.
- Implement worker-owned reusable scratch/arena storage.
- Precompile sample roles and population membership; only retain contiguous
  runs when profiling proves a gain.
- Reduce output segment creation and ordered publications without changing
  output bytes.

### 4. Build one capability QueryPlan

- Replace the separate generic need-fields, fused eligibility, and
  `FastSiteStatPlan` boolean rules with one immutable plan.
- Generate kernel choice, fallback reason, and log text from that plan.
- Extend one GT/DP/GQ/FT decode to feed multiple exact analyses and recode.

### 5. Apply only profile-supported higher optimizations

- Measure input/decompress, delimiter/FORMAT, GT parse, filter, statistics,
  format, ordered wait, commit, compression, allocations, and bytes.
- Evaluate adaptive batch sizing, deterministic chromosome analysis lanes,
  cache-blocked LD, runtime SIMD, and block-native BGZF in that order.
- Keep an optimization only when it has a stable benefit and no exact or
  cross-workload regression.
- Do not add GPU, fast-math, unconditional AVX, speculative NUMA binding,
  huge pages, or a raw-BCF performance rewrite without new evidence.

### 6. Verification ladder

1. Per-edit: build, warning-clean CTest, directed ASan/UBSan.
2. 23k DeepVariant and GATK: existing 45/45 and 95/95 plus new edge gates;
   include odd threads `1,2,3,4,5,7,8,11,16,31,32`.
3. 230k performance A/B after the design stabilizes; reuse locked Original
   artifacts and test `1,2,4,8,12,16,24,28,32` threads.
4. 2.3m exact gate at 8 and 16 threads only after the 230k candidate passes.
5. Full 11.23m release matrix only after code freeze and explicit user
   confirmation.

Primary performance inputs remain Plain VCF, BGZF VCF plus TBI, and BGZF VCF
without an index. BCF remains a compatibility path rather than the main
optimization target.

### 7. Performance acceptance

- Every scientific output must pass the applicable byte gate.
- No repeatable low-thread or primary-scenario wall-time regression greater
  than the agreed noise threshold (approximately 3%).
- A new scheduler/implementation must provide a meaningful stable gain or be
  removed/fallback-selected.
- Memory must remain bounded by the in-flight byte budget, not input size.
- The local host can validate only through 32 threads; 64-128 thread scaling
  must not be claimed without server evidence.
