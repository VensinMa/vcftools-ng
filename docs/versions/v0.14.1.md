# vcftools-ng v0.14.1 — Capability-Planned Exact Analytics

## Scope

v0.14.1 is the first formal release after v0.13.1. It incorporates the
unreleased v0.13.2 fused-filter work, then closes its correctness boundaries
and compiles every invocation into one immutable capability plan. The plan
selects required FORMAT fields, the exact execution kernel, and a stable
fallback reason before transactional scientific outputs are opened.

The compatibility oracle remains VCFtools 0.1.17. No tolerance comparison,
fast-math, `-march=native`, unconditional SIMD, GPU path, or fixed local-host
thread ceiling is used.

## Runtime changes

1. One `QueryPlan` is now the source of truth for required GT/DP/GQ/FT,
   chromosome, quality, allele, recode, filter, and analysis capabilities.
   Eligible VCF text kernels receive a compact immutable mask; unsupported
   combinations fall back as a whole to the general compatibility pipeline.
2. GT-only counts and FST no longer locate unused DP/GQ/FT fields. The
   production GT+DP+GQ filtering combination retains its specialized parser.
   Compatible outputs still share one record and sample scan.
3. Plain VCF, indexed BGZF, no-index BGZF, and BCF retain storage-native
   adapters. The no-index compressed stream uses an evidence-selected compute
   cap only inside its strict total thread budget; no 24/32-thread global cap
   was introduced.
4. LD stores its valid/heterozygous/homozygous-alt bit planes in one
   contiguous allocation and formats fixed 64-left-site blocks. Blocks are
   committed by ordinal, preserving exact pair and output order.
5. PCA materializes normalized dosage once in sample-major order. Each
   covariance cell continues to accumulate sites in input order before the
   unchanged legacy eigensolver step.
6. Release builds enable supported IPO/LTO. The reproducible two-stage PGO
   driver is opt-in for source builds and never enables a newer ISA baseline.

## Correctness and failure boundaries

- HTSlib EOF is distinguished from truncated, malformed, CRC, and I/O
  failures in stream and iterator paths.
- All scientific outputs remain transactional; reader/worker failure
  injection verifies cancellation, thread joining, rollback, and absence of
  partial publication.
- Legal headers without `##contig`, records larger than 8 MiB, zero selected
  samples, duplicate/nonexistent selectors, malformed numeric values, and
  unsorted/reappearing chromosomes have directed regression coverage.
- Floating options reject NaN and infinity.
- Automatic threads intersect scheduler, affinity, cgroup, hardware, and
  descriptor limits and remain capped at 128 only when `--threads` is
  omitted.
- Site-only filtering plus raw VCF recode preserves legal polyploid GT text as
  opaque data. Genotype-semantic commands reject ploidy above two before any
  scientific output is published.
- `--site-depth` and `--site-mean-depth` retain Original's 32-bit wrapping and
  degenerate formatting by default. `--corrected-depth-arithmetic` is an
  explicit vcftools-ng extension using checked 64-bit sums.

Original defects deliberately inherited by exact mode are catalogued in
[`original-vcftools-0.1.17-known-issues.md`](../original-vcftools-0.1.17-known-issues.md).

[`run-v0141-full-release-matrix.sh`](../../benchmarks/run-v0141-full-release-matrix.sh).
It verifies the complete BGZF/TBI, Plain VCF, BCF/CSI, and all three retained
Original goldens by size and SHA-256 before running. Original 0.1.17 is not
rerun: the unchanged v0.12.1 single-run timings and byte oracles are locked.

The first-repeat release gate uses all 11,230,392 records, the seven-filter
exact-recode workload, four input scenarios, and
`1/2/4/8/12/16/24/28/32` threads. It is strictly serial. Each candidate output

## Performance evidence and rejected work

On the locked 230k Plain fixture, final PGO improved counts, production
filters, and large/site-window FST by roughly 6%-15% relative to same-source
LTO. Recode, LD, and PCA were faster or inside the 3% noise threshold. Indexed
and no-index BGZF W01/W02 improved by roughly 3%-15%.

An allocation-free hand-written DP/GQ integer parser was rejected and fully
reverted after 40/40 exact hashes but repeatable 4.91%/6.13% regressions at
1/8 threads. A universal analysis-lane queue was also rejected because the
existing generic and fused engines already share one decode; it would add
copies and synchronization without removing a scan.

Full raw local evidence and the negative-result record are indexed by
[`v0.14.1-resume-plan.md`](v0.14.1-resume-plan.md). Performance values are
workload- and host-specific and are not claims for unmeasured 64-128-core or
multi-socket systems.
