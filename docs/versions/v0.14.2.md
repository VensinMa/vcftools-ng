# vcftools-ng v0.14.2 — Portable I/O Recovery

## Scope

v0.14.2 is a release-engineering and storage-path correction over v0.14.1.
The compatibility surface, immutable `QueryPlan`, parser semantics, ordered
reducers, and transactional output contract do not change. The release fixes
the gap between local optimized builds and the public portable archive, then
qualifies the fix with real portable-binary A/B runs.

## Diagnosed causes and accepted fixes

1. **Portable BGZF dependency.** v0.14.1's private HTSlib used zlib only.
   v0.14.2 pins libdeflate 1.25 by source SHA-256, builds HTSlib 1.24 with
   `--with-libdeflate`, bundles `libdeflate.so.0`, and includes its license.
2. **BCF stream planning.** Treating BCF like BGZF text capped HTSlib decode at
   three workers. The new strict plan reserves one reader, uses
   `ceil(total/4)` HTSlib decode workers from 3 threads upward, and gives the
   remaining budget to compute. The rule scales beyond the local 32-CPU host.
3. **Oversized Plain mmap.** Mapping the 122.9 GB complete VCF inflated RSS to
   about 100 GB and made parallel faults less effective than explicit aligned
   reads. Automatic mmap is now limited to 8 GiB; larger Plain inputs use the
   same bounded `pread` path that won the complete-data A/B. A development
   differential forces mmap and pread on the same fixture and compares output.

The proposed wider ordered-commit window was rejected after complete-output
1x/2x/4x A/B: it increased RSS and did not provide stable speedup. It was
fully reverted before the final build.

## Evidence

- Unified portable A/B: 3 versions × 3 inputs × 9 thread counts = **81/81
  PASS** initial outputs.
- Post-fix Plain output: all tested rows produced the locked 59,434,159,621
  byte file with SHA-256
  `d4f2a15e8c5ad0cc12abf4a3ab308bb48f22adf8ec13776d72ceeaa1f8d402b8`.
- The seven-filter workload always retained 5,425,725 of 11,230,392 sites.
- Release tests: **8/8 PASS**; ASan+UBSan: **8/8 PASS**.
- Input and TBI identities match the v0.14.1 locked assets.
- Portable archive passes clean CentOS 7 and Ubuntu 20.04 tests.

The complete tables, application/durable split, CPU, RSS, hashes, and logs are
under
[`full-unified-v0142-ab`](../../benchmarks/results/full-unified-v0142-ab/README.md).
The 5% equivalence band is a reporting rule, not a correctness tolerance;
scientific outputs still require exact bytes.
