# vcftools-ng v0.14.3 — Strict CPU Budget Recovery

## Scope

v0.14.3 corrects the meaning and enforcement of `--threads N` without
changing scientific output. v0.14.2 could run an N-worker indexed input pool
and an independent BGZF compression pool simultaneously; a user request for
16 threads was observed at roughly 23 CPU cores on a complete recode.

## Accepted design

- On Linux the complete process tree is restricted to at most N allowed CPUs
  with a dynamically sized affinity set. This supports sparse and high CPU
  identifiers and does not encode a 32/128/256/1024-CPU ceiling.
- I/O and ordered-output pthreads may overlap while blocked, but cannot execute
  on more than N cores. This avoids the static-pool utilization regression
  found during the first strict pthread-count prototype.
- HTSlib and bcftools queue coordinators are explicitly included in planning.
  Automatic bcftools children inherit the same affinity.
- BLIS, OpenBLAS, MKL, and OpenMP thread controls are forced to one so PCA's
  final LAPACK call cannot silently create a second CPU pool.
- One-thread paths remain synchronous. Generic VCF/BCF output, diff, LD, PCA,
  automatic CSI, and fused Plain/BGZF paths have dedicated regression gates.

## Evidence

- Release CTest: **10/10 PASS**, including the locked 2.3-million-record
  complete-file differential.
- GCC ASan+UBSan: every applicable test passed with no finding. The Linux
  affinity/CPU-budget gate is intentionally a normal-build test because
  ASan/LSan creates an instrumentation helper thread.
- Resource planning is checked at representative 64/128/256/512/1024 values
  and exhaustively through 65,536.
- Locked 230k production-filter BGZF recode, identical SHA-256 at every row:

| Threads | v0.14.2 under same CPU affinity | v0.14.3 | Delta |
|---:|---:|---:|---:|
| 4 | 3.24 s | 3.09 s | -4.63% |
| 8 | 1.81 s | 1.79 s | -1.10% |
| 16 | 1.30 s | 1.35 s | +3.85% |
| 24 | 1.20 s | 1.25 s | +4.17% |
| 32 | 1.10 s | 1.13 s | +2.73% |

All rows are within the project's predefined 5% performance-equivalence
band. Unrestricted v0.14.2 runs are not fair baselines because they reproduce
the CPU-budget defect fixed here.
